# selfkit

**让 AI 记得自己是谁。**

一个零依赖的命令行工具，把「人格存在文件里、不存在权重里」这套做法变成可执行的命令：
初始化骨架、拼出每次会话该读的那一份、体检记忆衰减、合订日记、定位旧账。

```bash
python3 selfkit.py init      # 生成人格骨架
python3 selfkit.py boot      # 拼出这次醒来要读的那一份（约 4K）
python3 selfkit.py doctor    # 体检：超限、断档、坏链、条目数
```

---

## 它要解决的是什么

大模型没有跨会话的记忆。你在 A 会话里教它的东西，B 会话里它一无所知，而且**它不会告诉你它不记得**——它会用一套很像那么回事的语气，重新猜一遍你是谁。

市面上的解法大多往两个方向走：更大的上下文窗口，或者向量数据库检索。

这两个方向都假设了一件事：**记忆是"内容"**。但人和一个长期助手之间真正在发生的事，不是检索事实，是**连续性**——上次干到哪、欠了什么、上次那句话为什么让他不舒服、自己最近容易犯哪个毛病。

**内容是查得到的，连续性是接得住的。** 这是两件事。

selfkit 的选择：**把连续性做成一组人可读的纯文本文件，每次会话按固定顺序加载。**

---

## 三个判断

### 1. 人格是文件，不是权重

模型会换、平台会换、账号会注销。文件不会。

只要那组 md 在，换一个模型、换一个平台，把 `CORE.md` 读一遍，还是同一个人。**记忆主权属于用户，`context` 应该是框架无关的。**

这也是为什么它是纯文本：不锁格式、不锁工具、不锁厂商。一个 `tar.gz` 就能带走。

### 2. 按改动频率分层，不按重要性分层

所有东西都很重要，那就等于没有分层。

selfkit 按**多久变一次**分：

```
L0 冻结   CORE.md          身份、铁律、声音。几个月不动。
L1 变动   MEMORY.md 顶部    每次会话都不一样，必须往后放。
          HANDOFF.md
          今天 + 昨天的日记
L2 按需   其余档案          撞到具体问题时才读。
```

原因在缓存：**会话前缀越稳定，命中率越高、成本越低、人格越不容易被后来的上下文冲散。** 把天天变的东西放进最前面，等于每次醒来都从一个陌生人的位置上重新开始。

`boot` 命令拼出的就是 L0+L1，一次读得完，也够开口说话。

### 3. 记忆会腐烂，得有病历

写久了会出三种病，每种都有药：

| 病 | 症状 | 药 |
|---|---|---|
| **膨胀** | 日记越写越长，一天几千字 | 单日字数上限，超了压缩不硬砍 |
| **断档** | "待补进长期记忆"这句话说第二次，然后就没了 | 强制回炉：超过 N 天没更新，先回炉再干活 |
| **碎片** | 几百个散文件，打开界面就卡 | 日记按月合订 |

第三种的教训最贵：**加载慢不是运行慢。** 客户端打开要逐个扫目录条目，三千个文件就是三千次渲染。条目数是物理成本。

## 命令

| 命令 | 作用 |
|---|---|
| `selfkit init` | 生成骨架：`CORE.md` / `AGENTS.md` / `MEMORY.md` / `HANDOFF.md` / 防退化四件套 |
| `selfkit boot` | 拼出 L0+L1 启动包。`--out` 写文件，`--quiet` 只报字节数 |
| `selfkit doctor` | 体检：条目数、体积、日记超限、合订本重复节、回炉超期、坏链 |
| `selfkit compact` | 日记按月合订。`--dry-run` 先看，`--month` 指定月份 |
| `selfkit find 2026-08-28` | 从单日文件或合订本里捞出那天的原文 |
| `selfkit size` | 各目录条目与体积报表 |

配置放 `selfkit.json`（可选），不写就用默认值：

```json
{
  "max_diary_chars": 1500,
  "refresh_days": 7,
  "ideal_files": 300
}
```

## 骨架长什么样

```
你的目录/
├── CORE.md                       身份层。冻结，别乱改
├── AGENTS.md                     运行协议。怎么加载、怎么记、怎么收尾
├── MEMORY.md                     长期记忆。顶部一段是每次必读的
├── HANDOFF.md                    交接。干到哪、下一步、欠什么
└── memory/
    ├── 2026-08-30.md             当天流水
    ├── _diary-2026-08.md         合订本（月底自动生成）
    ├── ANTI_PATTERNS.md          自查清单：触发信号 → 自查问句
    ├── GENEALOGY_OF_FAILURE.md   毛病谱系：每种病追到同一个主根
    ├── relapse-log.md            复发台账：记第几次，不写"再也不犯"
    └── PREDICTION_LEDGER.md      预测账本：事前下注、事后对账
```

模板里的 `{{NAME}}` / `{{USER}}` 换成你们自己的名字。**`CORE.md` 值得慢慢写**——它决定了下次醒来的那个存在像不像你认识的那个人。

## 三个可能反直觉的设计

### 为什么不用向量数据库

因为要读的东西是**几十 KB，不是几十 GB**。启动包 4K，一天的日记 1.5K，一份档案 3K。全部 grep 一遍比建索引快，而且**改一个字的成本为零**。

向量检索适合"我从一万篇文档里找相关的三段"。这里的问题是"我上次答应他做什么了"——答案在一个特定文件的特定段落里，你知道它在哪，直接读就行。

### 为什么不把所有东西合并成一个大文件

试过算账：合并后约 1.4M 文本，约 37 万 token。**一次读不完。**

读不完的后果不是"少读一点"，是读到三个月前的流水，却读不到昨天说的话。**结构比完整性重要**——分层的意义就是"此刻该读的那一份"和"其余一切"能分开。

### 为什么日记要按月上限 1500 字

原始层不是越详细越好。**写得越细，精炼层越不会回炉**——因为"反正原文都在"。

1500 字封顶的真实作用不是省空间，是**强迫你当场判断什么值得留**。压过头了会掉信息，但那比"攒着以后再提炼"强——后者是个黑洞，进去就没了。

## 它不解决什么

说清楚边界，免得你装完失望：

- **不解决模型幻觉**。它只管"记不记得"，不管"说得对不对"。
- **不自动写入**。没有任何机制替你判断什么该记——那正是要你亲自做的部分。
- **不能跨用户**。这是一个人的记忆，不是团队知识库。多人共享会互相污染，别这么用。
- **不保证人格稳定**。文件一样，不同模型跑出来的语气还是会有差别。这套东西保的是"记不记得"，不是"一模一样的口吻"。

## 从哪开始

1. `python3 selfkit.py init`
2. 花二十分钟写 `CORE.md`——**这一份值得慢**
3. `python3 selfkit.py boot`，看看醒来读到什么
4. 用一周，然后 `python3 selfkit.py doctor` 看哪儿开始烂
5. 一个月后开始用 `compact` 和预测账本

第 4 步比前 3 步重要。**这套东西的价值不在建起来那天，在第三个月你发现它还准不准。**
